# Douyin Browser Analysis Workspace Design

> 状态：已完成方案确认，待用户审阅后进入实施计划。  
> 所属模块：`src/renderer/entries/browser/App.tsx`  
> 关联代码：`src/renderer/entries/browser/components/WebViewContainer.tsx`、`src/renderer/shared/styles/globals.css`、`tests/unit/components/BrowserApp.test.tsx`  
> 关联规格：`docs/specs/automation-browser-ops-v1.md`

---

## 1. 背景

当前浏览器模块已经从“单纯标签页壳层”扩展为平台导向的采集工作台，抖音场景已具备以下基础能力：

- 平台入口与站点分类。
- 抖音运营工作台基础卡片。
- 评论草稿助手。
- 人工复核队列。
- 从复核队列生成自动化任务草案。

现状的问题是：搜索入口、当前分析对象、评论分析结论和下载动作还没有形成一条完整链路。用户只能停留在“打开抖音站点 + 记录备注 + 人工复核”的层级，无法围绕单条搜索结果形成稳定的分析流。

本设计把抖音模块收敛为一期主链路：

`搜索结果 -> 单条视频详情 -> 评论分析 -> 授权下载`

这样既能承接评论分析页目标，也能为后续账号洞察和搜索结果扩展保留结构。

---

## 2. 目标

- 在浏览器页内完成抖音搜索结果到单条视频分析的闭环，不新增独立模块入口。
- 将当前抖音工作台升级为三栏分析台，明确区分搜索样本、当前视频和分析动作。
- 让评论分析、评论草稿、人工复核都绑定到“当前视频”，而不是停留在平台级备注。
- 增加“授权下载”入口，但严格限定为单条、显式、人工确认的下载流程。
- 为后续账号洞察和搜索结果维度扩展预留状态与组件边界。

---

## 3. 非目标

- 不做账号主页聚合洞察的一期实现。
- 不做多视频批量分析。
- 不做批量下载、静默下载或后台自动下载。
- 不承诺无水印下载、不实现绕过平台限制的下载逻辑。
- 不做跨多条视频的趋势图表。
- 不在一期引入复杂持久化或新的本地数据库表。

---

## 4. 交互主链路

### 4.1 一期主线

用户进入浏览器模块后，选择抖音平台，在同一页内完成以下流程：

1. 输入关键词或话题，发起搜索。
2. 在结果列表中挑选一条目标视频。
3. 查看该视频的基础信息、评论抽样和页面采集状态。
4. 获取评论摘要、关键词、情绪倾向和风险提示。
5. 选择生成评论草稿、加入人工复核，或申请授权下载。

### 4.2 关键原则

- 搜索结果只是样本池，不自动覆盖当前分析对象。
- 所有分析动作都围绕当前选中的单条视频展开。
- 下载动作默认不可直达，必须先确认“自有内容 / 已授权内容”。
- 复核队列项必须带上当前视频上下文，避免只保存孤立文本备注。

---

## 5. 页面结构

抖音模块保留在现有 `browser/App.tsx` 的“抖音运营工作台”中，升级为三栏分析台。

### 5.1 左栏：搜索与样本池

职责是帮助用户从搜索结果里挑选要分析的视频，不承担深度阅读任务。

包含：

- 关键词输入框。
- 搜索按钮。
- 搜索结果筛选位。
- 搜索结果列表。
- 当前选中结果高亮态。

每条结果至少展示：

- 封面占位或缩略信息。
- 标题或话题摘要。
- 作者名。
- 发布时间标签。
- 互动量摘要。
- 是否已进入分析态。

### 5.2 中栏：当前视频分析对象

职责是承接用户当前正在处理的单条视频。

包含：

- 视频标题。
- 作者信息。
- 原始链接。
- 话题标签。
- 评论抽样。
- 页面采集状态。
- “申请授权下载”按钮。
- 下载状态与下载记录。

这一栏是评论分析页的核心对象区，不做多条视频聚合，避免与搜索结果列表混淆。

### 5.3 右栏：分析与动作台

职责是把已有评论草稿、人工复核和新分析结果聚拢到当前视频上下文。

包含：

- 评论摘要。
- 关键词提炼。
- 情绪倾向。
- 风险提示。
- 评论草稿助手。
- 人工确认动作。
- 待复核队列。

现有的评论草稿和复核能力继续保留，但不再是泛平台级，而是绑定当前视频。

## 6. 状态模型

一期不建议继续以零散 `useState` 累加复杂逻辑，至少需要在浏览器页内把抖音分析状态收拢为明确的数据模型。

### 6.1 `DouyinSearchItem`

表示左栏中的一条搜索结果。

```ts
interface DouyinSearchItem {
  id: string;
  title: string;
  authorName: string;
  publishLabel: string;
  url: string;
  coverUrl?: string;
  metricsSummary?: string;
  keywords?: string[];
}
```

### 6.2 `DouyinAnalysisTarget`

表示当前被选中并进入中栏分析的视频对象。

```ts
interface DouyinAnalysisTarget {
  item: DouyinSearchItem;
  pageTitle?: string;
  topicTags: string[];
  commentSamples: string[];
  captureStatus: 'idle' | 'loading' | 'ready' | 'error';
}
```

### 6.3 `DouyinCommentInsight`

表示右栏分析结论。

```ts
interface DouyinCommentInsight {
  summary: string;
  keywords: string[];
  sentiment: 'positive' | 'neutral' | 'negative' | 'mixed';
  riskFlags: string[];
}
```

### 6.4 `DouyinDownloadRequest`

表示单条视频的授权下载状态。

```ts
interface DouyinDownloadRequest {
  targetId: string;
  authorized: boolean;
  status: 'idle' | 'confirming' | 'ready' | 'downloading' | 'done' | 'error';
  confirmedAt?: string;
  savedPath?: string;
}
```

### 6.5 `DouyinReviewDraft`

表示当前视频下的草稿与复核状态。

```ts
interface DouyinReviewDraft {
  note: string;
  drafts: string[];
  selectedDraft?: string;
  queueItems: ReviewQueueItem[];
}
```

### 6.6 状态变更规则

1. 搜索成功后只更新左栏结果，不自动切换当前分析对象。
2. 用户点击结果后，才设置 `currentTarget`。
3. `currentTarget` 变化时，触发评论样本采集与分析生成。
4. 下载确认只影响当前对象的 `downloadState`，不影响结果列表。
5. 复核入队时，队列项必须携带当前视频标题或链接。

## 7. 交互行为

### 7.1 搜索与选中

- 用户输入关键词或话题后，点击“搜索抖音内容”。
- 左栏返回搜索结果列表。
- 用户点击某一条结果后，该结果进入选中态，并成为当前分析对象。
- 选中后，中栏展示该对象的基础信息，右栏进入对应分析上下文。

### 7.2 分析触发

当 `currentTarget` 更新时，同步触发两类处理：

- 页面采集：读取标题、作者、链接、可见评论样本和页面状态。
- 分析生成：基于评论样本生成摘要、关键词、情绪倾向和风险提示。

如果当前 tab 不在目标视频页，中栏仍展示搜索结果基础信息，但采集状态标记为待进入页面。

### 7.3 评论草稿

- 评论草稿生成必须基于当前视频标题、评论样本和关键词上下文。
- 草稿结果写回右栏，并允许用户一键写入备注区。
- 评论草稿仅作为人工确认前的建议，不进入自动发送流程。

### 7.4 人工复核

- 用户可把当前视频加入复核队列。
- 队列项必须包含视频标题、来源链接、当前备注和动作类型。
- 队列项生成执行任务时，应继承当前视频链接和动作上下文。

---

## 8. 授权下载按钮设计

### 8.1 按钮定位

下载按钮只出现在中栏，属于“当前视频分析对象”的动作，不出现在左栏结果列表中。

按钮文案采用“申请授权下载”，避免产生“点击即直接下载”的误解。

### 8.2 下载流程

点击按钮后按以下三步执行：

1. 进入确认态，要求用户明确勾选或确认“自有内容 / 已授权内容”。
2. 只有确认通过后，才展示“开始下载”按钮。
3. 下载完成后，在中栏记录视频标题、来源链接、确认时间和下载状态。

### 8.3 边界约束

一期仅支持以下能力：

- 单条视频下载。
- 显式人工确认。
- 下载状态可见。
- 授权素材归档入口。

一期明确不做：

- 批量下载。
- 后台静默下载。
- 自动跳过授权确认。
- 无水印能力承诺。
- 对未授权内容默认开放。

---

## 9. 组件拆分建议

为了避免 `browser/App.tsx` 持续膨胀，一期应把抖音分析台视图抽为独立子组件，但仍由浏览器页统一持有主状态。

建议新增或拆分：

- `DouyinAnalysisWorkspace`
- `DouyinSearchPanel`
- `DouyinTargetPanel`
- `DouyinInsightPanel`
- `DouyinDownloadPanel`

浏览器页负责：

- 平台切换。
- 当前 tab 信息。
- IPC 调用。
- 与现有复核队列、任务草案能力的桥接。

子组件负责：

- 局部展示。
- 当前视频上下文内的交互触发。
- 纯展示型状态反馈。

## 10. 测试策略

### 10.1 单元测试

覆盖：

- 搜索结果到当前分析对象的状态切换。
- 评论分析结论的基础数据转换。
- 授权下载确认状态机。
- 复核入队时的视频上下文拼装。

### 10.2 组件测试

覆盖：

- 左栏选中结果后，中栏和右栏同步切换。
- 右栏分析内容不会残留上一条视频的数据。
- 下载按钮默认需要先授权确认。
- 评论草稿会基于当前视频上下文生成。

### 10.3 集成测试

覆盖主链路：

1. 输入关键词并展示搜索结果。
2. 选中一条视频进入分析态。
3. 展示评论样本与分析结果。
4. 生成评论草稿。
5. 申请授权下载并进入确认流程。
6. 将当前视频加入复核并生成任务草案。

---

## 11. 验收标准

一期验收以以下 7 项为准：

1. 左栏能展示搜索输入、结果列表和当前选中态。
2. 选中一条结果后，中栏能展示当前视频基础信息。
3. 右栏分析区会跟随当前视频切换，不残留上一条内容。
4. 评论草稿生成基于当前视频上下文，而不是泛平台备注。
5. 下载按钮默认先走授权确认，未确认时不能直接开始下载。
6. 下载记录能显示来源视频和状态。
7. 复核队列项带上视频标题或链接，生成任务时可直接继承。

---

## 12. 实施边界与后续扩展

本设计故意只打通“搜索结果到单条视频评论分析”的主链路，不把账号主页洞察和搜索结果聚合分析一并塞入一期。

后续扩展顺序建议为：

1. 账号主页 -> 作品列表 -> 账号洞察。
2. 搜索结果批量样本对比。
3. 下载记录持久化。
4. 评论分析结果复用到自动化模板。

这样可以在不推翻三栏分析台结构的前提下，逐步把抖音模块做深。
