# 自动签到页面布局改版设计

## 目标

将当前“自动签到”页面从“左侧任务列表 + 右侧常驻表单/状态卡”的双栏布局，调整为更适合任务运营的“列表主导”布局：

| 项目 | 目标 |
| --- | --- |
| 页面主体 | 签到任务列表独占一行，成为主视图 |
| 新建/编辑 | 统一使用 Drawer 表单，不再常驻页面 |
| 结果查看 | 在表格下方固定展示“上一次结果”详情卡 |
| 列表可读性 | 使用 ProTable，自适应宽度，列内直接展示状态 |
| 运维动作 | 支持编辑、删除、立即执行 |

## 当前问题

| 问题 | 表现 |
| --- | --- |
| 双栏占用过大 | 列表和配置面板同时常驻，页面横向拥挤 |
| 新建反馈不直观 | 新建任务与编辑任务共用常驻表单，动作感不明显 |
| 列表信息不足 | 无法在列表中快速判断上一次执行结果 |
| 结果区域耦合 | 状态卡依附右栏，和任务列表切换耦合太强 |

## 方案

### 1. 页面结构

| 区域 | 内容 |
| --- | --- |
| 顶部操作区 | `新建签到任务`、`刷新`、工作区切换 |
| 主内容区 | 一张 ProTable，独占整行 |
| 详情区 | 表格下方固定一张“上一次结果”详情卡 |
| 表单区 | Drawer，仅在新建/编辑时打开 |

### 2. 列表列设计

| 列名 | 内容 |
| --- | --- |
| 任务名 | 任务名称 |
| 站点 | 当前固定显示京东 |
| 启用状态 | 启用 / 停用 |
| 最近执行时间 | 统一按北京时间展示 |
| 上一次结果 | 仅显示 `成功` / `失败` Tag |
| 操作 | `编辑`、`删除`、`立即执行` |

### 3. 交互设计

| 动作 | 行为 |
| --- | --- |
| 点击 `新建签到任务` | 打开 Drawer，载入默认草稿 |
| 点击 `编辑` | 打开 Drawer，载入当前任务配置 |
| 点击表格行 | 刷新下方“上一次结果”详情卡 |
| 点击 `删除` | 二次确认后删除任务，随后清空下方详情区 |
| 点击 `立即执行` | 触发运行，并刷新列表状态与详情卡 |

### 4. 上一次结果详情卡

| 字段 | 展示 |
| --- | --- |
| 状态 | success / needs_intervention / failed 等 |
| 策略 | browser / api-fallback / manual-retry |
| 最近执行时间 | 北京时间 |
| 错误原因 | failureReason |
| 执行说明 | detail |
| 运行记录 | history 列表 |
| 调试信息 | 页面标题、页面地址、DOM 摘要、截图预览 |

## 技术设计

| 模块 | 处理方式 |
| --- | --- |
| `src/renderer/entries/signin/App.tsx` | 重写布局状态，改为 `ProTable + Drawer + 固定结果卡` |
| `SigninTaskPanel` | 保持表单主体，改为嵌入 Drawer 使用 |
| `TaskList` | 不再作为签到页主列表容器，签到页会改用更贴近业务的独立表格实现 |
| 运行状态卡 | 继续复用 `SigninRunStatusCard`，但放到表格下方固定展示 |
| 删除能力 | 需要补主进程/渲染层删除链路，或复用已有 `task:delete` 能力 |

## 风险与边界

| 风险 | 应对 |
| --- | --- |
| 删除影响旧入口 | 自动化页中的签到入口暂不删除，只调整独立签到页 |
| 列表与详情状态同步复杂 | 选中行作为单一数据源，删除/新建后统一重置 |
| 表单 Drawer 状态残留 | 新建和编辑使用显式草稿重置逻辑 |

## 验收标准

| 编号 | 标准 |
| --- | --- |
| AC-1 | 签到页首屏显示单行自适应 ProTable，而不是左右分栏 |
| AC-2 | 点击 `新建签到任务` 后，以 Drawer 形式打开表单 |
| AC-3 | 点击 `编辑` 可用 Drawer 打开并回填已有任务 |
| AC-4 | 列表支持删除任务，并在删除后清空详情区 |
| AC-5 | 表格下方固定展示“上一次结果”详情卡 |
| AC-6 | 最近执行时间与结果历史统一显示北京时间 |
| AC-7 | “上一次结果”列仅显示成功/失败 Tag |
