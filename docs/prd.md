## 1. 产品背景与目标

现代桌面工作需要同时使用多种工具：股票分析、网页自动化、采集脚本、浏览器、多插件能力等。这些工具分散在不同软件中，不利于统一管理与工作流程整合。

本应用旨在打造一个可扩展、模块化、插件驱动的跨平台桌面工作台容器，使用户能在一个应用内高效完成多类复杂任务。

## 2. 产品定位

- 容器级桌面应用（Containerized Desktop Platform）
- 基于 Electron + React + Vite
- 支持多业务入口、多场景、多插件扩展
- 提供自动化、采集、分析、浏览等核心能力
- 可最终演进为一款桌面端的综合生产力平台

## 3. 用户角色与典型场景

### 3.1 用户角色

| 用户类型 | 需求点 |
|---|---|
| 数据采集工程师 | 自动化浏览器、采集策略、任务调度 |
| 量化研究员 | 股票行情、技术指标、策略测试 |
| 自动化工程师 | 网页 RPA、脚本执行 |
| 办公自动化用户 | 批处理任务、流程执行 |
| 高级用户 / 开发者 | 插件拓展、自定义工具 |

### 3.2 典型使用场景

#### 场景 A：数据采集工程师，电商价格监控

用户在「自动化采集」模块中创建任务流：打开目标电商页面 → 定位商品价格元素 → 提取数据 → 存入本地 SQLite → 设置每日定时执行。任务执行过程中可在「内嵌浏览器」中实时观察页面操作，异常时自动重试并记录日志。

#### 场景 B：量化研究员，技术指标分析

用户进入「股票分析」模块，接入行情数据源（WebSocket 实时推送），查看 K 线图并叠加 MA、MACD、RSI 指标。编写 JS 策略脚本，对历史数据进行快速验证，导出分析结果。

#### 场景 C：自动化工程师，网页表单批量填写

用户在「自动化采集」模块中录制表单操作流程（点击、输入、下拉选择），保存为任务模板。批量导入 CSV 数据，自动化引擎逐条执行填写任务，失败项标记后支持断点重试。

#### 场景 D：高级用户，插件开发与集成

开发者按照插件 API 规范开发 OCR 插件，声明所需权限（文件系统读取 + 网络访问），打包后通过「插件中心」安装。V1.0 中插件 UI 统一运行在受控的 `plugin-host` 宿主页内，仅允许受信来源插件接入；其他模块通过 IPC 调用 OCR 能力。

## 4. 整体功能架构

```text
+----------------------------------------------------------+
|                    Desktop Application                   |
|                  (Electron App Shell)                    |
+----------------------------------------------------------+
|  Multi-entry Workspace  |  Plugin Engine  |  Settings    |
+----------------------------------------------------------+
|          Module Communication Bus (IPC + Event)          |
+----------------------------------------------------------+
|   Analytics Engine   |   Automation Engine   | WebView   |
+----------------------------------------------------------+
|                System Services & Infrastructure          |
|  Logging | Permission | Storage | Config | Update | DB   |
+----------------------------------------------------------+
```

### 模块通信机制说明

- 主进程 ↔ 渲染进程：Electron IPC（contextBridge 安全暴露）
- 模块间事件分发：统一走主进程 EventBus + IPC fan-out，不依赖 BroadcastChannel
- 模块内状态共享：基于 Zustand + 持久化中间件
- 插件 → 宿主：通过 Plugin API Bridge（受限 IPC 通道，权限校验后转发）
- 事件总线：主进程维护全局 EventEmitter，各模块通过 IPC 订阅/发布事件

## 5. 详细模块说明

### 5.1 应用壳（App Shell）

- Electron 主进程（要求 Electron ≥ 28）
- 窗口管理、多窗口支持
- WebContentsView 容器管理
  - BrowserView 已在 Electron 28+ 废弃，统一使用 WebContentsView
- IPC 通信（基于 contextBridge 安全暴露 API）
- 系统菜单、托盘、更新器

### 5.2 多入口模块系统（Multi-entry Module System）

为每个业务场景创建独立入口，包括：

- 独立路由
- 独立状态管理
- 分离构建产物
- 可热加载 / 可禁用

技术实现方案：

- V1.0：基于 Vite 多入口（MPA 模式）构建，每个模块为独立 HTML 入口，通过动态 `import()` 实现模块懒加载
- V2.0：评估引入 Module Federation 实现跨应用模块共享与独立部署

示例模块：

- 股票分析
- 网页自动采集
- 内嵌浏览器
- 插件中心
- 自定义工具（Terminal、Markdown 编辑器等）

### 5.3 插件系统（Plugin Engine）

核心职能：

- 插件安装、卸载、启用、禁用
- 插件运行模型
  - V1.0：共享 `plugin-host` 宿主页 + 受限 preload
  - V1.5：升级为按插件独立进程
- 插件权限声明（例如：网络、文件系统、自动化权限）
- 插件 UI 加载
  - V1.0 统一通过 `plugin-host`
  - 不引入 `iframe`
- 插件 API（通过主进程 IPC 提供）

插件权限分级模型：

- Level 1（UI 只读）：仅允许渲染 UI、读取公开应用状态，无需用户授权
- Level 2（网络 + 存储）：允许网络请求、读写插件专属存储空间，安装时需用户确认
- Level 3（自动化 + 文件系统）：允许调用自动化引擎、访问用户文件系统、操作 WebContentsView，每次使用需用户显式授权

阶段规划：

- V1.0：实现基础权限声明 + 受信来源策略（官方 / 本地开发 / 手动允许列表）
- V1.5：升级为按插件进程级隔离 + 资源限制

可支持插件示例：

- OpenClaw 自动化能力
- OCR 模块
- PDF 处理器
- 爬虫脚本插件
- AI 推理插件（本地模型）

### 5.4 自动化与采集引擎（Automation Engine）

提供类似浏览器 RPA 的能力：

- DOM 查询
- 点击 / 输入 / 滚动行为模拟
- 页面内容采集
- 截图、选择器生成
- 任务流（Flow → Step → Action）
- 错误重试、断点继续

### 5.5 数据分析引擎（Analytics Engine）

用于金融或行情类分析：

- 行情数据源接入（REST / WebSocket）
- 技术指标库（MA、MACD、RSI、BOLL 等）
- 图表绘制（K 线、分时、指标叠加）
- 策略脚本执行（JS / Python）
  - JS 策略：在 Worker 线程或沙箱 VM 中执行
  - Python 策略：V1.0 通过 `child_process.spawn()` 调用本地 Python 环境执行脚本，通过 stdin/stdout JSON 协议通信；V2.0 评估 Pyodide（WASM）方案实现无依赖 Python 运行时
- 回测框架（未来扩展）

### 5.6 内嵌浏览器（Embedded Web Workspace）

- 多标签页
- 按工作区或配置文件的会话隔离（Cookie / LocalStorage）
- 受控脚本执行（仅自动化引擎内部生成或审核通过的脚本模板）
- 可被自动化引擎控制（通过 WebContentsView.webContents API）
- 支持任务化自动浏览

### 5.7 配置中心

- 全局配置
- 模块配置
- 插件配置
- 自动化任务配置
- 配置文件可备份 / 导出

### 5.8 日志中心

- 应用运行日志
- 自动化任务日志
- 插件日志
- 错误分析
- 导出调试包

### 5.9 权限与安全模块

- 插件权限沙箱（三级权限模型，详见 5.3）
- 文件读取白名单
- WebContentsView 注入安全控制（受控脚本模板、导航白名单、preload 暴露面最小化）
- IPC 消息安全校验（schema 校验 + 频率限制）
- 应用密钥管理

### 5.10 数据存储模块（Data Storage）

数据持久化方案：

- 结构化数据（任务配置、股票数据、插件元信息、用户设置）：SQLite（通过 better-sqlite3 同步访问）
- 大文件 / 二进制（采集截图、导出文件、日志归档）：应用数据目录文件系统存储
- 临时缓存 / 渲染进程数据：IndexedDB（浏览器原生）
- 配置文件：JSON / YAML 文件（便于备份导出）

数据目录结构：

- `{userData}/databases/`：SQLite 数据库文件
- `{userData}/storage/`：大文件存储
- `{userData}/config/`：配置文件
- `{userData}/logs/`：日志文件
- `{userData}/plugins/`：插件安装目录

## 9. 非功能性需求

### 性能

- 启动时间 < 2s（冷启动到主界面可交互）
- 模块动态加载（单模块加载时间 < 1s）
- 插件宿主隔离不影响主界面性能（主进程 CPU 占用 < 5%）
- 内存占用 < 500MB（基础模块全部加载状态）
- 单插件加载时间 < 500ms
- 并发自动化任务支持 ≥ 5 个
- SQLite 查询响应 < 50ms（常规查询）

### 安全性

- 插件权限声明机制（三级权限模型）
- 文件系统访问限制（白名单 + 沙箱目录隔离）
- IPC 通信校验（schema 校验 + 频率限制）
- WebContentsView 脚本注入限制（受控脚本模板 + 导航控制）

### 可扩展性

- 模块化结构（Vite 多入口独立构建）
- 插件可独立分发（标准 `.ycplugin` 包格式）
- 插件市场（未来）

- 自动化引擎基础版
