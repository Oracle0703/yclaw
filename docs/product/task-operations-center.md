> 本文档基于现有 `docs/product/prd.md`、`docs/overview/roadmap.md`、`docs/specs/automation-browser-ops-v1.md`、`docs/specs/remote-runner-control-plane-v1.md` 与 `docs/specs/capacity-aware-runner-scheduler-v1.md` 进行需求深化。
> 目标不是替代现有架构，而是在既有自动化、Runner、AI、插件和结果体系之上，明确一条更完整的业务主线：**面向 3~20 人团队的任务运营中台**。

## 2. 主线重新定义

### 2.1 一句话定位

> YClaw 是一个面向小团队的桌面端任务运营中台，用于统一编排、执行、监控、复盘和复用自动化任务。

### 2.2 核心价值

| 价值点 | 说明 | 当前已有基础 |
| --- | --- | --- |
| 任务资产化 | 任务不再只是临时脚本，而是可版本化、可审核、可复用的业务资产 | Task、Template、Task-as-Code |
| 执行可运营 | 团队能统一查看排队、执行、失败、重试、人工介入和恢复过程 | Batch、Result、Runner、Scheduler |
| 异常可处理 | 出错后不是简单失败，而是可告警、可定位、可转交、可接管 | Log、Alert、Browser Intervention |
| 结果可沉淀 | 执行结果可汇总、可导出、可回看、可反哺模板与规则 | Result Center、Export、Review |
| 能力可扩展 | OCR、验证码识别、通知、数据清洗等能力可以插件化接入 | Plugin Host、Permission System |
| 决策可辅助 | AI 可以基于任务上下文进行诊断、总结和建议 | AIService、ToolRegistry |

### 2.3 与“自动化工具”的区别

| 维度 | 普通自动化工具 | YClaw 任务运营中台 |
| --- | --- | --- |
| 关注点 | 单次执行是否成功 | 任务全生命周期是否可持续运营 |
| 使用对象 | 单个操作者 | 任务配置员 + 值班执行员 + 负责人 + 分析员 |
| 结果处理 | 看日志、人工判断 | 结构化结果、失败归因、复盘与资产沉淀 |
| 异常响应 | 失败后手动重跑 | 告警、派单、人工接管、断点恢复 |
| 能力复用 | 复制脚本 | 模板复用、插件复用、规则沉淀 |

## 3. 目标用户与组织模型

### 3.1 团队规模假设

| 项目 | 范围 |
| --- | --- |
| 推荐团队规模 | 3~20 人 |
| 使用形态 | 同一业务组内共享任务资产与操作规范 |
| 协作模式 | 本地为主、局域网 / 内网远程 Runner 辅助，不以云多租户为前提 |

### 3.2 角色定义

| 角色 | 核心职责 | 典型操作 |
| --- | --- | --- |
| 运营负责人 | 关注任务 SLA、风险、资源利用率和团队效率 | 看总览、审批关键任务、查看告警、分派处理 |
| 任务配置员 | 负责任务设计、步骤编排、模板维护、调试 | 新建任务、编辑流程、配置模板、联调插件 |
| 执行值班员 | 负责日常监控、失败介入、重试和交接 | 查看执行队列、处理告警、手动接管、恢复运行 |
| 数据分析员 | 关注结果产出、质量、趋势和导出 | 查看结果、比对批次、导出报表、追踪异常数据 |
| 插件管理员 / 开发者 | 提供扩展能力并维护能力边界 | 安装插件、声明权限、发布能力组件 |

### 3.3 协作边界

| 能力 | 是否纳入本阶段 |
| --- | --- |
| 任务共享与指派 | 是 |
| 审批与操作留痕 | 是 |
| 值班交接与人工介入 | 是 |
| 团队看板与异常聚合 | 是 |
| 多租户、组织树、部门权限 | 否，属于后续平台化阶段 |
| 云同步与在线多人实时协同编辑 | 否，属于后续阶段 |

## 4. 核心业务对象

### 4.1 业务对象总览

| 对象 | 说明 | 关键字段示例 |
| --- | --- | --- |
| 工作区 Workspace | 团队的协作边界和默认配置容器 | 名称、成员、默认 Runner 池、通知策略 |
| 任务 Task | 可执行的业务单元 | 任务名、负责人、优先级、状态、调度方式 |
| 任务版本 Task Revision | 某次任务定义快照 | 版本号、修改人、变更摘要、审核状态 |
| 任务流 Flow | 由多个步骤组成的执行逻辑 | Step 列表、变量、重试策略、超时策略 |
| 模板 Template | 可复用的任务配置骨架 | 分类、输入参数、适用站点、版本 |
| 执行批次 Batch | 某次调度或手动触发的运行批次 | 触发来源、开始时间、结束时间、总结果 |
| 执行实例 Execution | 批次中的具体运行实例 | Runner、状态、日志、截图、错误码 |
| Runner | 本地或远程执行资源 | 类型、能力、容量、健康状态、占用率 |
| 告警 Alert | 需要关注和处理的异常事件 | 级别、来源、归因、处理人、处理状态 |
| 结果集 Result Set | 任务产出的结构化结果集合 | 批次、数据摘要、校验状态、导出状态 |
| 复盘 Review | 对失败或异常批次的归因与结论沉淀 | 原因分类、处置结论、后续动作 |
| 插件能力 Plugin Capability | 可插入任务链路的扩展能力 | OCR、验证码识别、通知、清洗、导出 |

### 4.2 对象之间的关系

```text
Workspace
  ├─ Task
  │   ├─ Task Revision
  │   ├─ Flow / Template
  │   ├─ Batch
  │   │   ├─ Execution
  │   │   ├─ Result Set
  │   │   └─ Alert / Review
  │   └─ Assigned Runner Policy
  └─ Plugin Capability / Notification Policy / Members
```

## 5. 业务闭环与生命周期

### 5.1 标准运营闭环

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| 需求收集 | 明确为什么要做这个任务 | 任务目标、输入输出、成功标准 |
| 任务编排 | 形成可执行任务流 | Task、Flow、变量、模板 |
| 审核发布 | 控制高风险改动上线 | 审核记录、发布版本 |
| 调度执行 | 让系统按计划运行 | Batch、Execution、Runner 分配 |
| 异常处理 | 在失败发生时快速响应 | Alert、介入记录、重试记录 |
| 结果验收 | 判断产出是否符合业务预期 | Result Set、质量校验、导出 |
| 复盘沉淀 | 让经验回流到任务资产 | Review、模板更新、规则优化 |

### 5.2 任务状态机

| 状态 | 含义 | 可流转到 |
| --- | --- | --- |
| 草稿 | 尚未可执行，配置中 | 待审核、已废弃 |
| 待审核 | 等待负责人确认或发布 | 已发布、退回修改 |
| 已发布 | 可手动或定时触发 | 排队中、暂停中、已下线 |
| 排队中 | 等待 Runner 资源 | 执行中、已取消 |
| 执行中 | 正在运行 | 成功、失败、需人工介入、已取消 |
| 需人工介入 | 自动执行遇阻，需要人工判断 | 执行中、失败、已终止 |
| 成功 | 本次执行完成且通过基础校验 | 已复盘、已归档 |
| 失败 | 本次执行失败 | 重试中、需人工介入、已复盘 |
| 已复盘 | 已形成结论与动作建议 | 已归档、重新发布 |
| 已归档 | 暂不继续活跃运营 | 重新发布 |

### 5.3 告警状态机

| 状态 | 含义 | 可流转到 |
| --- | --- | --- |
| 新告警 | 系统新发现异常 | 已指派、已忽略 |
| 已指派 | 已明确处理人 | 处理中、已升级 |
| 处理中 | 正在分析和介入 | 已恢复、已关闭、已升级 |
| 已升级 | 超出值班能力，升级给负责人 | 处理中、已关闭 |
| 已恢复 | 问题已解决，任务恢复执行 | 已关闭 |
| 已关闭 | 告警生命周期结束 | — |

## 6. 关键业务场景深化

### 6.1 场景 A：电商价格巡检

| 维度 | 业务逻辑 |
| --- | --- |
| 目标 | 每日巡检重点商品价格、库存与促销信息 |
| 输入 | 商品列表、站点规则模板、登录态、巡检时间窗 |
| 执行 | 系统按调度批量执行，优先分配到具备对应浏览器环境的 Runner |
| 异常 | 登录失效、页面结构变化、触发验证码、库存字段缺失 |
| 处理 | 值班员收到告警后在浏览器介入台接管，恢复会话后继续执行 |
| 结果 | 结构化输出价格对比、异常商品列表、截图证据、站点成功率 |
| 沉淀 | 若 DOM 结构变更高频发生，则更新模板或增加站点适配插件 |

### 6.2 场景 B：表单批量提报

| 维度 | 业务逻辑 |
| --- | --- |
| 目标 | 将 CSV / Excel 数据批量填报到外部系统 |
| 风险点 | 字段映射错误、单条数据异常、验证码、人审页面阻断 |
| 协作点 | 配置员负责模板与字段映射，值班员负责执行监控，负责人审批正式执行 |
| 中台价值 | 记录每一批次成功率、失败记录、重试次数与人工介入时长 |

### 6.3 场景 C：跨站点数据汇总

| 维度 | 业务逻辑 |
| --- | --- |
| 目标 | 多站点拉取数据后统一清洗、聚合并输出 |
| 流程 | 采集任务 → 结果入库 → 插件清洗 → 指标聚合 → 导出报告 |
| 协作点 | 数据分析员关注结果质量，插件管理员维护清洗插件，负责人查看日报 |
| 中台价值 | 把“执行成功”升级为“结果可用且可追踪” |

### 6.4 场景 D：值班交接

| 维度 | 业务逻辑 |
| --- | --- |
| 目标 | 保证异常任务在交班时不丢上下文 |
| 核心要求 | 每个异常批次需附带处理进展、截图、下一步建议、当前阻塞点 |
| 中台支持 | 交接备注、责任人变更、待办视图、按严重级别排序 |

## 7. 功能需求深化

### 7.1 工作区与协作

| 功能 | 需求说明 |
| --- | --- |
| 工作区管理 | 支持按团队创建工作区，绑定成员、默认配置、任务标签和通知规则 |
| 成员角色 | 至少支持负责人、编辑者、值班员、查看者四类基础角色 |
| 操作留痕 | 任务发布、审批、指派、重试、终止、介入、导出都要有审计记录 |
| 交接机制 | 支持将任务、告警或值班责任转交给其他成员，并记录交接说明 |

### 7.2 任务中心

| 功能 | 需求说明 |
| --- | --- |
| 任务分层 | 区分草稿任务、已发布任务、归档任务、系统模板生成任务 |
| 任务标签 | 支持按业务线、站点、风险等级、负责人、结果类型打标签 |
| 版本与发布 | 每次发布形成任务版本，支持回看历史版本、变更摘要和前后版本差异 |
| 审核机制 | 高风险任务或涉及 Level 3 权限能力的任务发布前必须审批 |
| 优先级 | 支持 P0 / P1 / P2 或紧急 / 高 / 中 / 低优先级 |

### 7.3 执行运营中心

| 功能 | 需求说明 |
| --- | --- |
| 执行视图 | 展示队列、运行中、待介入、最近失败、Runner 占用和成功率 |
| 批次视图 | 每次批次可查看触发来源、使用版本、执行路径、异常节点 |
| Runner 策略 | 支持本地优先、远程优先、指定能力优先、容量优先等分配策略 |
| 调度策略 | 支持定时、手动、事件触发三类基础触发方式 |
| 干预控制 | 支持暂停、继续、重试、跳过步骤、人工接管、终止 |

### 7.4 告警与值班中心

| 功能 | 需求说明 |
| --- | --- |
| 告警分级 | 至少支持提示、警告、严重三级 |
| 告警来源 | 支持执行失败、超时、结果异常、Runner 离线、插件异常 |
| 处理流 | 告警需支持认领、升级、备注、恢复、关闭 |
| 值班视图 | 为值班员提供按严重度、负责人、等待时长排序的工作台 |

### 7.5 结果中心

| 功能 | 需求说明 |
| --- | --- |
| 结果聚合 | 结果按任务、批次、站点、时间区间聚合查看 |
| 质量校验 | 可定义结果校验规则，例如字段缺失、数量异常、阈值偏差；基础版先落地必填字段与最小批次数量规则 |
| 跨批次分析 | 可按任务汇总多个批次的总结果数、失败数、缺失必填字段数、可追溯结果数与批次质量状态 |
| 证据链 | 结果应关联日志、步骤、截图、页面快照、人工备注 |
| 导出 | 支持导出 CSV、JSON、调试包或运营报告 |

### 7.6 模板与资产中心

| 功能 | 需求说明 |
| --- | --- |
| 模板分类 | 按站点、任务类型、插件依赖、适用场景分类 |
| 复制创建 | 模板可一键复制成任务 |
| 模板维护 | 模板支持版本、废弃标记、适用说明、依赖插件说明、样例输入 |
| 经验回流 | 复盘结论可转化为模板改进建议、可执行回流草稿、模板治理更新、选择器字段改写或必填校验项 |

### 7.7 AI 运营副驾驶

| 功能 | 需求说明 |
| --- | --- |
| 任务问答 | 查询任务状态、最近失败原因、Runner 资源情况 |
| 故障摘要 | 自动总结失败批次的共性问题与可能归因 |
| 操作建议 | 给出重试建议、切换 Runner 建议、介入建议、模板优化建议 |
| 复盘助手 | 根据日志、结果、截图生成复盘初稿 |
| 风险提示 | 在发布高风险任务或权限过高的插件组合时给出提醒 |

### 7.8 插件能力市场化前置

| 功能 | 需求说明 |
| --- | --- |
| 能力声明 | 插件不仅声明权限，还声明“业务能力类型”和适用任务链路 |
| 插件编排 | 允许在任务流中插入 OCR、验证码、通知、清洗、导出等能力节点 |
| 能力评分 | 为后续市场化预留“稳定性 / 使用次数 / 最近失败率”指标 |
| 安全限制 | 业务能力接入仍必须遵循权限校验与来源策略 |

## 8. 关键业务规则

### 8.1 发布与审核规则

| 规则编号 | 规则 |
| --- | --- |
| R-001 | 新建任务默认为草稿，不得直接进入定时调度 |
| R-002 | 涉及文件系统写入、自动化控制或高风险外部站点的任务，发布前必须审批 |
| R-003 | 任务版本一经发布，不可直接覆盖运行中的批次 |
| R-004 | 已发布任务修改后必须形成新版本，旧版本仍可用于历史批次追踪 |

### 8.2 执行与调度规则

| 规则编号 | 规则 |
| --- | --- |
| R-101 | 同一任务可配置并发上限，避免对目标站点造成冲击 |
| R-102 | 同一工作区下的高优任务可抢占低优先级待执行资源 |
| R-103 | Runner 被标记为异常时，不得继续接收新任务 |
| R-104 | 同一批次内的失败重试必须记录重试原因和次数 |
| R-105 | 进入“需人工介入”状态后，系统应冻结自动重试，等待人工操作结果 |

### 8.3 告警与处理规则

| 规则编号 | 规则 |
| --- | --- |
| R-201 | 严重告警必须具备责任人，不能长期处于无人认领状态 |
| R-202 | 超时未处理的严重告警应自动升级给负责人 |
| R-203 | 告警关闭前必须填写处理结论或关闭原因 |

### 8.4 结果与复盘规则

| 规则编号 | 规则 |
| --- | --- |
| R-301 | 结果导出必须标识来源任务、批次、版本和导出时间 |
| R-302 | 连续失败达到阈值的任务必须进入复盘流程 |
| R-303 | 复盘完成后，应至少落一项后续动作：模板更新、插件调整、选择器修复、调度策略修正之一 |
| R-304 | 结果质量分析必须同时输出任务级汇总与批次级状态，便于定位是单批次波动还是模板规则退化 |
| R-305 | 自动化页展示的验收指标必须来自统一服务端口径，不允许前端临时拼接不同统计规则 |

## 12. 成功标准

| 指标 | 目标 |
| --- | --- |
| 任务交接完整率 | 交接任务中 95% 以上包含必要上下文 |
| 任务执行成功率 | 成功批次占比达到 90% 以上 |
| 失败处理时长 | 严重告警平均响应时间小于 10 分钟 |
| 结果追溯完整率 | 95% 以上结果可关联任务、批次、日志、截图 |
| 模板复用率 | 新建任务中 50% 以上来自模板复制 |
| AI 辅助有效率 | 50% 以上失败批次可生成有帮助的摘要或建议 |
| 复盘资产回流率 | 80% 以上复盘记录应关联模板回流或规则修复动作 |

## 13. 与现有架构的对齐说明

| 现有能力 | 在中台主线中的角色 |
| --- | --- |
| Automation Engine | 任务执行内核 |
| FlowRunner | 任务流执行与断点恢复执行器 |
| Remote Runner / Scheduler | 资源调度与执行资源池 |
| Browser Module | 人工介入和现场恢复操作台 |
| Result / Batch / Alert 体系 | 执行可运营的核心数据资产 |
| AI Assistant | 运营副驾驶，而非单纯聊天工具 |
| Plugin System | 任务链路中的能力扩展层 |

> 结论：YClaw 现有架构无需推翻，只需要在产品定义、业务对象、状态机、协作流程和页面入口上进一步收敛，即可从“多能力桌面容器”升级为“任务运营中台”。
