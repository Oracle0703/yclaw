# 📋 YClaw 自动化采集产品化实施计划（V1）

> 定位：以自动化采集为核心，浏览器作为调试、观察、接管执行的介入台  
> 适用范围：聚焦 `自动化采集 + 浏览器工作台`，不覆盖现有 `docs/plan.md`

---

## 1. 目标与边界

### 1.1 一期目标

| 项 | 说明 |
| --- | --- |
| 产品目标 | 做成一个可日常使用的自动化采集桌面产品 |
| 核心闭环 | 建任务 → 定时执行 → 查看结果 → 异常介入 → 复跑 |
| 用户角色 | 以数据采集工程师、自动化工程师为主 |
| 浏览器定位 | 不是独立主产品，而是自动化任务的观察台、调试台、接管台 |

### 1.2 一期不纳入重点

| 方向 | 处理方式 |
| --- | --- |
| 股票分析深化 | 降级为后续扩展，不占一期主资源 |
| 插件生态化运营 | 保留基础能力，不做市场化扩展 |
| AI 自主调度 | 保留助手入口，不作为主链路 |
| 超复杂流程编排 | 不做可视化大编排器，先保证核心采集闭环 |

---

## 2. 产品策略

### 2.1 推荐路线

| 路线 | 描述 | 结论 |
| --- | --- | --- |
| 任务中心 + 浏览器介入台 | 以自动化调度为主，任务异常时允许人工接管当前浏览器会话继续处理 | 一期正式路线 |

### 2.2 核心价值

| 价值 | 说明 |
| --- | --- |
| 自动执行 | 任务可以按计划稳定运行，减少重复人工操作 |
| 可观察 | 每次执行都有状态、日志、截图、结果记录 |
| 可介入 | 失败时可以接管页面，完成登录、验证、修正后继续 |
| 可追溯 | 结果、规则、批次、失败原因统一关联 |
| 可复用 | 常见站点可沉淀模板，不需要每次重新配置 |

## 4. 核心用户流程

### 4.1 主流程

| 阶段 | 用户动作 | 系统行为 |
| --- | --- | --- |
| 建任务 | 选择目标站点、设置入口页、录制动作、配置提取字段 | 保存任务定义与规则模板 |
| 配调度 | 设置执行周期、重试策略、超时阈值、绑定会话 | 注册调度计划并写入执行队列 |
| 自动运行 | 用户不介入 | 调度器触发，执行引擎自动跑任务 |
| 异常处理 | 查看失败任务并接管页面 | 浏览器介入台恢复到失败现场 |
| 结果处理 | 查看结果、筛选、导出、复跑 | 关联批次、日志、截图与提取结果 |

### 4.2 失败闭环

| 场景 | 系统响应 |
| --- | --- |
| 页面元素变化 | 标记步骤失败，保存 DOM 快照与截图 |
| 登录态失效 | 暂停任务并提示接管当前会话 |
| 验证码 / 人机校验 | 进入人工介入状态，人工处理后继续 |
| 站点限流 | 延迟重试或终止当前批次 |
| 提取结果异常 | 标记结果为可疑，进入人工复核队列 |

## 5. 实施路线

### 5.1 Phase 1：任务闭环落地（P0）

| 目标 | 关键交付 |
| --- | --- |
| 先跑通自动化主链路 | 任务中心、调度器、执行队列、基础规则定义、结果入库 |
| 建立最小可用产品 | 支持创建任务、手动执行、定时执行、查看状态、失败重试 |

### 5.2 Phase 2：浏览器介入能力（P0）

| 目标 | 关键交付 |
| --- | --- |
| 让自动化可接管 | 浏览器介入台、失败现场恢复、会话绑定、执行恢复 |
| 降低失败处理成本 | 一键打开失败现场并继续当前任务 |

### 5.3 Phase 3：结果与稳定性增强（P1）

| 目标 | 关键交付 |
| --- | --- |
| 提升日常可用性 | 结果中心、批次对比、导出、异常筛查、模板复用 |
| 提升稳定性 | 告警、日志检索、失败归因、性能与资源优化 |

## 6. 里程碑建议

| 里程碑 | 周期 | 交付内容 |
| --- | --- | --- |
| M1 基础自动化闭环 | 2-3 周 | 任务创建、手动执行、执行日志、结果入库 |
| M2 调度与复跑 | 2 周 | 定时任务、失败重试、批次状态、复跑入口 |
| M3 浏览器介入台 | 2-3 周 | 失败接管、当前页面观察、恢复执行 |
| M4 结果中心 | 1-2 周 | 结果列表、批次详情、导出与筛选 |
| M5 稳定化 | 1-2 周 | 告警、资源治理、体验收尾、回归验证 |

## 7. 非功能要求

| 维度 | 目标 |
| --- | --- |
| 可用性 | 常见任务配置流程清晰，非开发者也能完成基础配置 |
| 稳定性 | 长时间运行不因单个任务失败导致整体调度失控 |
| 可观测性 | 每次执行均可追踪状态、日志、截图、异常原因 |
| 可恢复性 | 失败任务能接管、重试、复跑，不需要从头创建 |
| 性能 | 常见单任务执行过程中界面保持可交互，结果查询响应稳定 |

## 8. 成功标准

### 8.1 产品级成功指标

| 指标 | 目标 |
| --- | --- |
| 任务主链路 | 支持任务创建、调度、暂停、恢复、复跑 |
| 失败介入能力 | 失败任务可恢复到可观察、可接管的页面现场 |
| 结果可追溯性 | 每条结果可关联任务、批次、规则、日志、截图 |
| 模板复用能力 | 常见站点任务可保存为模板并二次复用 |
| 日常可用性 | 用户能把它作为日常采集主工具持续使用 |

### 8.2 建议验收指标

| 指标 | 目标值 |
| --- | --- |
| 任务执行成功率 | 在稳定站点场景下达到可接受水平并持续可优化 |
| 失败可定位率 | 大多数失败任务可从日志和截图快速定位原因 |
| 失败可介入率 | 关键失败场景支持人工接管后继续执行 |
| 结果导出可用率 | 支持按任务和批次导出结构化结果 |
