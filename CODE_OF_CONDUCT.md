# Code of Conduct

## Our Standard

YClaw is intended to be a respectful, technically rigorous, and collaborative open-source project. Contributors and maintainers are expected to create an environment where people can discuss ideas, review code, and disagree on technical decisions without personal attacks or hostile behavior.

Examples of behavior that contributes to a healthy community include:

- using respectful, concrete, and professional language
- assuming good intent while still challenging weak technical reasoning
- giving actionable review feedback instead of dismissive comments
- focusing criticism on code, design, tradeoffs, and behavior rather than individuals
- helping keep discussions accessible to contributors with different experience levels

Examples of unacceptable behavior include:

- harassment, discrimination, or insulting language
- personal attacks, intimidation, or sustained antagonistic behavior
- deliberately derailing issues, pull requests, or technical discussions
- publishing private information without explicit permission
- any conduct that would reasonably make participation unsafe or hostile

## Scope

This Code of Conduct applies to project spaces, including:

- issues
- pull requests
- discussions
- review comments
- documentation and design conversations

It also applies when an individual is representing the project in public spaces.

## Enforcement

Project maintainers are responsible for clarifying and enforcing these standards. They may remove, edit, or reject comments, commits, code, issues, and other contributions that violate this Code of Conduct.

Maintainers may take any action they deem appropriate, including:

- private warning
- temporary restriction from participation
- removal of content
- long-term or permanent ban from project spaces

## Reporting

If you experience or witness unacceptable behavior, report it to the project maintainers through the repository contact channel or by opening a private maintainer contact where available.

When reporting:

- describe what happened
- include links or references if relevant
- note whether you are requesting confidentiality

Maintainers will review reports in good faith and handle them as discretely as practical.

## Project Interpretation

This repository values direct technical feedback and strong engineering standards. Firm disagreement is acceptable; disrespect is not. The line is simple: be precise, be critical when needed, and remain professional.
